# ADR-0008: APIキー管理にSSM Parameter Storeを採用

- Status: Accepted
- Date: 2026-07-18

## Context

OpenAIとCohereのAPIキーをコードやテンプレートに露出させずに保管し、Lambdaから安全に参照する必要がある。AWSのシークレット保管サービスにはSecrets ManagerとSSM Parameter Storeがあり、費用と機能が異なる。課題は、安全性と固定費ゼロ方針の両立である。

## Decision

SSM Parameter StoreのSecureStringパラメータでAPIキーを管理する。値はLambdaの初回参照時に取得し、実行環境が再利用される間はキャッシュした値を用いる。

採用理由は次の2点である。

- 標準パラメータは保管と取得が無料で、課金されるのはSecureStringの復号に伴うKMSの呼び出しのみである。キャッシュするため、取得は実行環境あたり1回であり、額は無視できる
- KMSによる暗号化とIAMによるアクセス制御で安全性を確保できる

## Consequences

メリット

- 固定費ゼロ方針であるADR-0001を維持できる
- キーの参照権限をLambdaの実行ロールに限定できる

デメリット・制約

- 自動ローテーション機能がなく、キーの更新は手動運用となる
- 実行環境ごとに値をキャッシュするため、キー更新の反映にはLambda実行環境の入れ替えが必要になる

見直し条件

- キーの定期ローテーションが必須要件になった場合はSecrets Managerを再検討する

## Alternatives

### Secrets Manager

自動ローテーションとバージョン管理を備えるが、シークレットごとに月額の固定費が発生する。ローテーションを組むにはSaaSごとの鍵発行APIを叩くLambdaが必要で、そこまでの要件がないため不採用とした。

### Lambda環境変数への直接設定

取得処理が不要で最も単純だが、コンソールやCDKテンプレートにキーが平文で露出する。安全性の要件を満たさないため不採用とした。
