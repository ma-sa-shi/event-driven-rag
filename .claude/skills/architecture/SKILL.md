## このドキュメントの目的

architecture.mdはシステム全体の構成を説明する設計書である。

読者がシステム全体を理解できることを目的とし、設計判断の詳細な議論や比較検討は記載しない。設計判断の根拠、代替案、トレードオフはADRへ記録する。

## ドキュメント構成

次の順序で記述する。

1. タイトル
2. 目次（H2/H3まで）
3. 本文

## 文体ルール

- タイトル直後に目次を作成する（H2/H3まで）
- 括弧による補足説明は原則禁止（略語の正式名称を示す場合のみ許可）
- 図には前後に説明文を書く
- 用語は文書内で統一する
- 本文だけで理解できるように記述し、図は補助として扱う
- 箇条書きは8項目以内とし、超える場合は分類する
- 文末表現を単調にしない
- 一般的な技術解説は書かず、本システムにおける役割のみ説明する
- 「○○とは」の説明は必要最小限とする
- 「詳細は○○参照」は最小限とする

## 記述ルール

- システム全体を俯瞰できる構成にする
- 各章では「何を採用したか」と「その目的」を簡潔に説明する
- Whyは1〜3文程度に留める
- 比較検討やトレードオフはADRへ記載する
- 同じ内容を複数箇所へ記載しない
- ADRへの参照は必要最小限とし、同じ内容を繰り返し参照しない
- ドキュメントは設計書として記述し、技術解説書にはしない

## 完成前チェック

- [ ] タイトル直後に目次がある
- [ ] 図の前後に説明がある
- [ ] 用語が統一されている
- [ ] 本文だけで内容を理解できる
- [ ] Whyが簡潔に説明されている
- [ ] 一般的な技術解説を書いていない
- [ ] 詳細な設計判断はADRへ分離されている
- [ ] 同じ内容やADR参照を繰り返していない
